# dev-team Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `dev-team/`, an eight-profile Hermes team. It runs a fixed
intake → plan → implement → validate → review → pr-ci pipeline on Hermes kanban, and a plugin
guards each stage's completion with forge-agnostic checks.

**Architecture:**
- Kanban and its dispatcher are unchanged.
- The `dev-team-gate` Hermes plugin's `pre_tool_call` hook validates each stage card's
  `kanban_complete` metadata, checks the card topology, and enforces the round limit. For pr-ci it
  re-reads CI through the `forge` CLI. It also blocks merge, deploy and kanban-CLI side doors in
  `terminal`.
- `forge` is a stdlib Python CLI with one JSON contract and four vendor adapters.
- The installers mirror the outsourcing-team ones.

**Tech Stack:**
- Python 3 stdlib only (`unittest`, `urllib`, `subprocess`)
- bash (3.2-compatible)
- PowerShell 5.1
- GitHub Actions, only for this repository's own CI

**Spec:** `docs/superpowers/specs/2026-10-29-dev-team-design.md`

## Global Constraints

- Python stdlib only. No third-party imports in `forge` or the plugin, which run under whichever
  Python Hermes provides.
- `forge` exit codes: `0` ok, `1` negative result, `2` cannot verify. Every subcommand prints one
  JSON object to stdout.
- CI states are exactly `green` | `red` | `pending` | `none`.
- Stage skill names are `dev-team-stage-<stage>`, with stage in `intake`, `plan`, `implement`,
  `validate`, `review`, `pr-ci`.
- Round limit: 3 `implement` cards in a card's ancestry.
- The guard fails closed. Any exception or unverifiable state produces a block with a reason.
- Block reasons and attention labels start with a class label: `ci: other`,
  `review: rounds-exhausted`, `forge: unreachable`, `merge: human-only`, `budget: exhausted`.
- Profile prefix default is `dev-`. Profile base names are `pm architect uiux backend-db frontend
  qa reviewer devops`.
- Team state lives under `$HERMES_HOME/dev-team/`:
  - `projects/<slug>.json`
  - `repos/<slug>/`
  - Never written into the target repository.
- Credentials are never written to the project record, stdout JSON or logs.
- bash 3.2 compatible: no `declare -A`, no `${var,,}`. PowerShell 5.1 compatible: no `?.`, no
  ternary.
- Re-running either installer is idempotent.

## Review Focus

- A worker calls `kanban_complete` with no `task_id` (it defaults to `HERMES_KANBAN_TASK`). The
  guard must resolve the id the same way (`test_complete_defaults_task_id_from_env`).
- The forge is unreachable or slow during pr-ci completion. That must block with
  `forge: unreachable` within the hook budget, never pass (`test_pr_ci_forge_unreachable_blocks`).
- A non-dev-team card in the same Hermes install must pass through untouched
  (`test_unguarded_card_passes`).
- A rework card three levels deep: the fourth `implement` child must be refused, and
  `kanban_block` must still be allowed (`test_fourth_round_refused_block_allowed`).
- The installer is re-run after the old teams are installed. It must not touch `sdlc-team` or
  outsourcing profiles (`test_prefix_isolation` in the CI job: an unprefixed `qa` profile survives
  unchanged).

### Task 5: Gate: board view and the `kanban_complete` check

**Files:**
- Create: `dev-team/plugin/dev-team-gate/board.py`, `dev-team/plugin/dev-team-gate/guard.py`,
  `dev-team/plugin/dev-team-gate/tests/test_guard.py`

**Interfaces:**
- Consumes: `stages.*` (Task 4).
- Produces:
  - `TaskView(id: str, skills: list[str], parents: list[str], children: list[str])`
  - `class Board(Protocol)` with `task(id) -> TaskView | None` and
    `last_metadata(id) -> dict | None`
  - `KanbanBoard()`, the real implementation. It uses `hermes_cli.kanban_db_connect.connect(board=os.environ.get("HERMES_KANBAN_BOARD"))`,
    `kanban_db.get_task`, `parent_ids`, `child_ids` and `latest_run(...).metadata`. It is imported
    lazily so the tests never import Hermes.
  - `implement_rounds(board, task_id) -> int`, which counts `implement` cards on the ancestry path,
    including the task itself
  - `check_complete(board, task_id, args, ci_status: Callable[[str, str], str]) -> str | None`,
    where `None` lets the call through and a string is the block message
- Rules, in this order:
  1. Unguarded card → None.
  2. `validate_metadata` errors → block.
  3. `head_sha` equals the parent stage card's `last_metadata["head_sha"]` for validate, review
     and pr-ci.
  4. `created_cards` contains exactly one card whose stage is `expected_child`, and that card
     lists `task_id` as a parent. When the expected child is `None`, no child is required.
  5. When the child is `implement` and `implement_rounds(child) > 3`, block with
     `review: rounds-exhausted`.
  6. For pr-ci, `ci_status(slug, head_sha)` must return `green`. An exception becomes
     `forge: unreachable`.

### Task 6: Gate: terminal guard and plugin wiring

**Files:**
- Create: `dev-team/plugin/dev-team-gate/{plugin.yaml,__init__.py}`; extend `guard.py` and
  `tests/test_guard.py`

**Interfaces:**
- Produces:
  - `check_terminal(board, task_id: str | None, command: str) -> str | None`
  - `pre_tool_call(tool_name, args, **kw) -> dict | None`, which returns
    `{"action": "block", "message": msg}` or `None`
- Terminal rules:
  - Always block, with `merge: human-only`:
    - `gh pr merge`, `glab mr merge`, `tea pr(s) merge`
    - `git push` whose refspec targets the record's `default_branch`
    - `kubectl apply|rollout`, `helm upgrade|install`, `terraform apply`, `docker push`
  - On a guarded card, also block `hermes kanban (complete|request-changes|edit|unblock|reopen-review)`.
  - Tokenise with `shlex.split` and match on argv. Never use a substring regex on the raw string.
- `pre_tool_call` dispatch:
  - `kanban_complete` → `check_complete` with the task id from `args.task_id` or
    `HERMES_KANBAN_TASK`
  - `terminal` → `check_terminal`
  - Anything else → None
- `ci_status` calls `forge ci-status` as a subprocess with timeout 20s, under the 30s hook budget.
- The slug comes from the intake card's metadata `repo`, found by walking ancestors.
- `plugin.yaml` has `name: dev-team-gate` and `provides_hooks: [pre_tool_call]`.

  - `test_push_to_default_branch_blocked_feature_branch_allowed`
  - `test_kanban_cli_side_door_blocked_on_guarded_card_only`
  - `test_complete_defaults_task_id_from_env`
  - `test_kanban_block_never_guarded`
  - `test_quoted_merge_in_commit_message_not_blocked`, which runs `git commit -m "gh pr merge"`
